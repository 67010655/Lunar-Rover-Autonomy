# แผนการทดลองและ Milestone 1

วันที่เริ่ม: 24 ตุลาคม 2026 — ผู้ใช้อนุมัติให้เริ่มงานจากแผน simulation รอบแรกในบทสนทนา เอกสารนี้เป็นแผนพัฒนาและสมมติฐานของต้นแบบ ไม่ใช่บันทึกการอนุมัติรายละเอียดทั้งหมดโดยอาจารย์

## 1. คำถามของโครงงาน

1. ระบบระบุตำแหน่งที่มีและไม่มีข้อมูลตำแหน่งอ้างอิงจำลองมีความคลาดเคลื่อนและผลต่อการเดินทางต่างกันอย่างไร?
2. การเพิ่ม terrain cost และ communication risk เปลี่ยนระยะทาง ความเสี่ยง และผลสำเร็จอย่างไร?

แนวทางหลังประชุมครั้งที่ 1 ที่ผู้ใช้แจ้งเพิ่มการเปรียบเทียบ localization เข้ากับ P0/P1/P2 ในสไลด์เดิม ส่วนรูปแบบ estimator, เซนเซอร์จำลอง, lunar ROI และเกณฑ์งานวิจัยสุดท้ายยังต้องกำหนด

## 2. สิ่งที่ส่งมอบใน Milestone 1

สนามสังเคราะห์หนึ่งฉาก + P0 + รถจำลองแบบป้อนกลับ + บันทึกตำแหน่งจริง/ประมาณ + กราฟ/CSV/manifest ไม่ต้องใช้รถจริงหรือข้อมูลดวงจันทร์เพื่อผ่าน milestone นี้

### พิกัดและความปลอดภัยของเส้นทาง

- พิกัด `map_local_m`: x ไปทางขวา, y ขึ้นด้านบน; yaw วัดทวนเข็มจาก +x หน่วย rad
- JSON ใช้ `[row, column]`; row เพิ่มตาม +y; เซลล์อ้างอิงที่กึ่งกลาง ขอบเขต obstacle rectangles รวมเซลล์ปลายทั้งสอง
- ฉากตัวอย่าง 60 × 48 cells ที่ 0.25 m/cell = **15 × 12 m** เป็นขนาดสนามเสมือน ไม่ใช่ขนาดดาดฟ้าหรือ ROI ดวงจันทร์
- ตัวรถเป็นวงกลมรัศมี 0.18 m; planning margin 0.12 m เป็นค่าพัฒนาต้นแบบ ไม่ใช่ขนาดรถที่ยืนยัน
- P0 บนกริด 8 ทิศ ใช้ระยะ Euclidean ในหน่วย m; ห้ามตัดมุมและห้ามผ่าน hard obstacles
- Planner ตรวจ clearance ด้วยรัศมี 0.30 m; evaluator ตรวจรัศมีตัวรถจริง 0.18 m ระหว่างก้าวด้วย
- ตัวควบคุมใช้ estimated pose เท่านั้น GT ใช้สร้างเซนเซอร์สังเคราะห์ ตรวจชน และประเมินผล ผู้ประมาณตำแหน่งไม่ได้รับ GT โดยตรง

### กรณีตรวจซอฟต์แวร์

| Mode | วัตถุประสงค์ |
|---|---|
| ideal | ตรวจว่า P0 และตัวควบคุมพารถถึงเป้าหมายเมื่อ odometry ไม่มี error |
| odometry | ตรวจผลของ noise/bias ต่อวงควบคุมจริง |
| fixes | ตรวจช่องทางรับข้อมูล absolute position เป็นช่วง ๆ |

ทั้งสามเป็นโมเดลพัฒนาซอฟต์แวร์ **ไม่ใช้แทนผลเปรียบเทียบ GNSS/SLAM ขั้นสุดท้าย** ไม่มีการอ้างว่าใส่ noise ลง GT แล้วเท่ากับทำ SLAM

พารามิเตอร์ noise เป็นค่าที่ตั้งเพื่อพัฒนาต้นแบบ ยังไม่มีการสอบเทียบกับฮาร์ดแวร์ ไม่ใช้ผลรอบนี้เป็นการยืนยันความแม่นยำของเซนเซอร์

### เกณฑ์ผ่านรอบแรก

- P0 ให้ระยะตรงตาม Dijkstra บนแผนที่ทดสอบขนาดเล็ก รวมทางตันและ diagonal cases
- ideal วิ่งถึง goal tolerance จริงโดยไม่ชนและไม่ป้อน GT ให้ controller
- seed และ input เดิมให้ trajectory/metrics เชิงจำลองเดิม ยกเว้น wall-clock planning time และ metadata การรัน
- noise มีผลต่อ estimated pose และการควบคุมจริง
- แยก success, collision, timeout, estimated-goal-only และ no-path ไม่แสดงผลล้มเหลวเป็นสำเร็จ
- outputs มีหน่วย config snapshot และ source/output checksums

## 3. การทดลองเป้าหมายหลังต้นแบบเสถียร

| ระบบระบุตำแหน่ง | P0 ระยะทาง | P1 ระยะทาง + ภูมิประเทศ | P2 ระยะทาง + ภูมิประเทศ + การสื่อสาร |
|---|---|---|---|
| A: มี GNSS จำลอง/ตำแหน่งอ้างอิง ตามแบบที่ตกลง | A0 | A1 | A2 |
| B: ไม่มี GNSS จำลอง พร้อมวิธีระบุตำแหน่งที่ตกลง | B0 | B1 | B2 |

ชื่อ A0–B2 ใน repo อ้างอิงเลข P0–P2 โดยตรง; ถ้าเอกสารเดิมเรียก A1–A3/B1–B3 ต้องระบุ mapping ให้ชัดก่อนรวมตาราง

มีสองการออกแบบที่ตอบคนละคำถาม:

- **ผลของ absolute fixes:** ใช้ estimator/เซนเซอร์พื้นฐานชุดเดียวกัน แล้วเปิด/ปิด fixes เพื่อแยกผลของข้อมูลอ้างอิง
- **เปรียบเทียบทั้งระบบ:** GNSS+IMU+odometry เทียบ Visual หรือ LiDAR SLAM+IMU+odometry ผลจะรวมความต่างของทั้งระบบ จึงอ้างไม่ได้ว่าเกิดจาก GNSS เพียงอย่างเดียว

ต้องเลือกรูปแบบหลักก่อนเรียกผลว่า GNSS-assisted/denied comparison หากใช้ SLAM ต้องมี observation จำลองและอัลกอริทึมประมาณตำแหน่ง/แผนที่จริง กำหนด map-frame alignment และ initialization ด้วย

### ความเป็นธรรมและตัวชี้วัด

- P0/P1/P2 ใช้ hard no-go/clearance, จุดเริ่มต้น เป้าหมาย และฉากเดียวกัน; P0 ยังต้องหลบสิ่งกีดขวาง
- คำนิยาม/normalization ของ terrain cost, link risk และน้ำหนักต้องบันทึกก่อนทดลอง
- แบ่ง development/validation/test scenarios ก่อนปรับ noise/weights; ตัวอย่างใน repo เป็น development เท่านั้น
- ทำซ้ำหลายฉาก หลาย seed และจัดคู่ seed ในการเปรียบเทียบ จำนวนรวม = จำนวนระบบ × planner × ฉาก × repeats ไม่ใช่เพียง 6 runs
- วัด localization RMSE [m], final error [m], planned/executed path [m], mission time [s], success rate [%], terrain exposure และ comm outage [s] ตามโมเดลที่นิยาม
- รายงานจำนวนตัวอย่าง failures และ uncertainty; ถ้ายังไม่มี radio model อย่ารายงาน outage/PDR เสมือนวัดแล้ว
- แผนที่ล่วงหน้าและจุดเริ่ม/จบเดียวกันอาจให้เส้นทาง global เหมือนกันใน A/B ความต่างต้องเกิดใน execution หรือกำหนดการใช้ estimated pose ใน replanning ไว้ชัดเจน

## 4. ลำดับถัดไป

1. ตรวจผล Milestone 1 กับทีม/อาจารย์ กำหนดคำถาม localization หลักและเลือก Visual หรือ LiDAR เมื่อจำเป็น
2. เพิ่ม P1/P2 บน synthetic cost layers พร้อมตัวอย่างที่ตรวจได้และการทดสอบ baseline
3. เลือก lunar ROI/DEM พร้อม metadata, CRS, resolution และ no-data; แยก synthetic data ออกจาก lunar data
4. เพิ่ม estimator/เซนเซอร์จำลองที่ตรงขอบเขต แล้วออกแบบ repeated experiments ทั้ง matrix
5. พิจารณารถจริงหลังยืนยันความจำเป็น ขนาด กลไก งบ และความปลอดภัย

ไม่มีการกำหนดเส้นตาย 4 หรือ 8 เดือนเป็นข้อเท็จจริงจากสไลด์เก่า ต้องอิงกำหนดส่งจริงของทีม
